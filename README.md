# opencode-gitwt

Git worktree для OpenCode: изоляция сессий, подготовка окружения и явная очистка.
Ядро перенесено из нашего Bash-скилла `git-wt` в JavaScript. Один пакет содержит
плагин и самостоятельный CLI с привычными флагами.

Требования: Node.js от 22.14, Git, OpenCode от 1.19.3 до 2.0.
Плагин использует API переноса сессии этой версии OpenCode.

## Подключение

После первого релиза в npm добавьте в `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-gitwt@0.1.0"]
}
```

Для подключения из SourceCraft замените имя пакета в `plugin` на Git-spec:

```text
git+https://git@git.sourcecraft.dev/voischev/opencode-gitwt.git#<commit>
```

Укажите нужный хеш коммита вместо `<commit>`. Исходники готовы к исполнению:
сборка и install-скрипты для Git-установки не нужны. Для локальной разработки
в `plugin` можно указать абсолютный `file://`-путь к `src/index.js`.

После подключения перезапустите OpenCode.

## Инструменты агента

- `gitwt_create`: создать worktree, подготовить окружение, перенести контекст
  в отдельную сессию, открыть терминал.
- `gitwt_list`: показать worktree, владельцев, dirty/ahead/behind и состояние
  подготовки.
- `gitwt_remove`: явно удалить worktree, проверить lease и попытаться удалить
  слитую ветку.

Пример аргументов `gitwt_create`:

```json
{
  "branch": "feature/login",
  "base": "main",
  "open": true
}
```

Передавайте ровно одно из `branch` или `description`. `branch` сохраняет
регистр и слеши; описание преобразуется в slug, русский текст транслитерируется.
Итоговое имя с prefix проверяется через `git check-ref-format`.

По умолчанию стартовая точка — свежая remote-ветка: `trunk`, затем `main`, затем
`master`, затем remote HEAD. Fetch выполняется с одной повторной попыткой.
`from: "HEAD"` позволяет явно начать от локального коммита без fetch.
`reuse: true` подключает уже существующую свободную ветку. База при этом
игнорируется. Занятые ветки и существующие каталоги не перезаписываются.

По умолчанию контекст форкается, а новый fork **переносится в каталог worktree**
через control-plane API с `moveChanges: false`. После переноса каталог сессии
проверяется. Сообщения сессии сохраняются штатным fork API. Если установлены
плагины OCX/kdco, дополнительно копируются их `plan.md` и файлы делегирования
из каталогов `workspace` и `delegations` в data-каталоге OpenCode.
Простой `chdir` не используется как замена переносу сессии. Ошибка переноса
откатывает только созданный fork; worktree остаётся с состоянием `session_failed`.

`fork: false` создаёт worktree без переноса контекста. `open: false` отключает
автоматический терминал. В ответе возвращаются путь, ID сессии, владелец lease
и массив команды запуска. Ошибка терминала сохраняет сессию и worktree,
отражается в `terminal.success` и состоянии `terminal_failed`.

## CLI

После публикации можно установить CLI командой `npm install -g opencode-gitwt`.
Из клонированного репозитория он доступен через `node bin/git-wt.js`.

```bash
git-wt "исправить вход" --json
git-wt --slug feature/login --base main --prefix agent/
git-wt --slug experiment --from HEAD --path "/tmp/my worktree"
git-wt --slug feature/existing --reuse
git-wt --slug parallel --lease-owner agent-1 --lease-reason task-123
git-wt list --status --json
git-wt config
git-wt remove parallel --lease-owner agent-1
```

Создание поддерживает `--remote`, `--base`, `--from`, `--prefix`, `--dir`,
`--path`, `--setup`, `--reuse`, `--lease-owner`, `--lease-reason`, `--open`.
`--open` запускает новую сессию OpenCode без переноса контекста: работа с SDK
доступна только плагину. `--json` выдаёт один JSON-объект в stdout, ошибки —
JSON в stderr с ненулевым exit code. `--porcelain` выдаёт строки `key=value`;
вложенные значения сериализуются как JSON. Вывод дочерних команд захватывается
и не загрязняет машинный stdout.

## Настройки

Приоритет от низшего к высшему:

1. Значения по умолчанию.
2. Первый найденный `~/.git-wt` или `~/.config/git-wt.yml`.
3. `~/.config/opencode/gitwt.jsonc`.
4. `.git-wt.yml` в исходном worktree.
5. `.opencode/gitwt.jsonc` в исходном worktree.
6. Параметры плагина из `opencode.json`, затем явные аргументы инструмента/CLI.

Объекты `sync` и `hooks` объединяются по ключам; массивы заменяются целиком.
Конфиги автоматически не создаются. Ошибочные настройки прерывают операцию.
Поддержаны прежние YAML-ключи `worktree_dir`, `post_create`, `pre_remove`.

Пример `.opencode/gitwt.jsonc`:

```jsonc
{
  "remote": "origin",
  "base": "auto",
  "prefix": "agent/",
  "worktreeDir": "~/worktrees",
  "forkSession": true,
  "terminal": "auto",
  "sync": {
    "copyFiles": [".env.local"],
    "symlinkDirs": ["node_modules"],
    "exclude": ["**/*.log"]
  },
  "hooks": {
    "postCreate": [["npm", "run", "prepare:worktree"]],
    "preRemove": [["docker", "compose", "down"]]
  }
}
```

Без `worktreeDir` сохраняется схема `~/git-wt/<путь_репо_от_HOME>/<ветка>`.
Для репозитория вне HOME и для настроенного `worktreeDir` используется
namespace `<имя_репо>-<id>`, чтобы одноимённые проекты не конфликтовали.
`--path` задаёт полный путь; `~` раскрывается и в конфиге, и в CLI.

`copyFiles` принимает относительные пути к файлам и каталогам. `exclude`
работает как glob. Отсутствующий источник, конфликт назначения, `.git`,
выход за пределы корня или вложенный симлинк при копировании — явная ошибка.
Существующие файлы не удаляются и не перезаписываются. `symlinkDirs` намеренно
делит каталог с исходным worktree, поэтому изменения в нём будут общими.

Команды хуков и `setup` принимают argv-массив или строку. Массив исполняется
без shell; строка является явной shell-командой (`bash -c` / `cmd /c`).
В хуках доступны `BRANCH`, `WORKTREE_PATH`, `HEAD`; cwd — целевой worktree.
Ошибки не скрываются. Хуки из конфига исполняют код с правами пользователя.
Команды `preRemove` сохраняются при создании worktree, поэтому удаление из
другой ветки использует те же настройки окружения. Явные параметры удаления
могут переопределить этот список.

## Терминалы

`terminal: "auto"`: текущий tmux → доступный контекст cmux → терминал среды.
Можно указать backend явно или поставить `"none"`.

Поддержаны tmux, cmux, Terminal.app, iTerm, Ghostty, Kitty, WezTerm, Alacritty,
GNOME Terminal, Konsole, xterm и Windows Terminal. OCX-контекст сохраняет
бинарник и профиль. `launchCommand` позволяет задать собственный argv запуска.
Нативные GUI-адаптеры требуют проверки на соответствующей ОС; автоматические
тесты проверяют их команды и экранирование, а не наличие всех терминалов.
Warp пока возвращает ручную команду вместо ложного успеха запуска.

## Состояние и очистка

Состояние находится в `<git-common-dir>/opencode-gitwt`, отдельно от рабочих
файлов. Каждый worktree имеет собственную атомарно записываемую запись;
операции сериализуются межпроцессной блокировкой. Lease не создаёт untracked
файл и не делает worktree грязным. Для удаления leased-worktree нужен точный
owner; отсутствие owner и `force` проверку не обходят.

Удаление запускается только явно. Текущий worktree плагин удаляет на следующем
`session.idle` **с тем же session ID**. Другие idle-события не вызывают очистку;
несколько отложенных удалений не перезаписывают друг друга. При ошибке worktree
и запись остаются, ошибка видна в `gitwt_list`. Из CLI удаляйте worktree из
основного или другого worktree, а не из удаляемого каталога.

Незакоммиченные изменения блокируют удаление, в том числе созданные preRemove.
Только явный `force: true` / `--force` разрешает их потерю. Плагин не создаёт
snapshot-коммиты, не делает push/reset/clean. После удаления запускается
`git branch -d`; неслитая ветка сохраняется с предупреждением. Для сохранения
ветки задайте `keepBranch: true` / `--keep-branch`. После merge PR удалите
worktree из актуальной основной ветки. При squash-merge Git может потребовать
отдельного решения пользователя об удалении ветки: автоматического `-D` нет.

## Разработка и публикация

```bash
npm ci --ignore-scripts
npm run check
npm test
node scripts/release.js --check
```

Тесты используют реальные временные Git-репозитории. При наличии OpenCode
1.19.3 дополнительно запускается изолированный `opencode serve`: проверяются
регистрация инструментов и перенос сессии в worktree без вызова LLM.
Для сквозной проверки Git-установки задайте `GITWT_TEST_PLUGIN_SPEC` равным
Git-spec из раздела подключения и запустите `node --test test/session.test.js`.
Сервер использует отдельные HOME, npm-конфиг и XDG-каталоги.

SourceCraft CI проверяет PR в `main`, push в `main` и release-теги `v*`.
Перед публикацией проверяются тесты, линт, совпадение тега с `package.json`,
совпадение HEAD с тегом, вхождение коммита в свежую историю `origin/main`,
отсутствие версии в npm и полнота tarball. Секреты в tarball запрещены.

Для первой публикации:

1. Создайте granular-токен npm с правом публикации нового пакета
   `opencode-gitwt` и bypass 2FA для CI. Для создания нового пакета токен
   должен разрешать создание пакетов, а не только запись в существующие.
2. В SourceCraft: настройки репозитория → секреты → `NPM_TOKEN`.
3. Влейте PR в `main` и обновите локальную основную ветку.
4. Создайте тег версии, например `v0.1.0`, на влитом коммите и отправьте тег.
5. Проверьте workflow `release` и появление версии в npm.

Токен передаётся только кубику публикации. Временный `.npmrc` создаётся вне
репозитория и удаляется после команды. npm Trusted Publishing для SourceCraft
не поддерживается, поэтому workflow использует токен.
