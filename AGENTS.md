# Работа с opencode-gitwt

## Назначение и границы

- Это тонкий адаптер OpenCode к npm-пакету `@voischev/gitwt`.
  Git-логику и CLI меняйте в отдельном репозитории `gitwt`, не копируйте сюда.
- `src/index.js` регистрирует `gitwt_create`, `gitwt_list`, `gitwt_cd`, `gitwt_remove`.
  Используйте `ctx.directory` и передавайте `ctx.abort` ядру.
- Агент продолжает текущую сессию и использует возвращённый `worktreePath`.
  `gitwt_cd` не меняет cwd. Не добавляйте терминалы, форки сессий и очистку по idle.
- Конфиг ядра: `.gitwt.json` и `~/.config/gitwt/config.json`, обычный JSON.

## Изменения и зависимости

- Минимальные правки, JavaScript ESM, без этапа сборки.
- Runtime-зависимости: `@voischev/gitwt` и `zod` для схем инструментов OpenCode.
  Biome используется только при разработке. Не добавляйте зависимости без необходимости.
- README короткий, на английском, с примером запроса агенту. Описания инструментов
  и аргументов — на английском, тесты — на русском. Комментарии только для неочевидных причин.
- npm-зависимость ядра должна указывать на опубликованную версию, не на локальный
  каталог. При изменении API сначала выпустите ядро и обновите lock-файл адаптера.

## Проверка

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run release -- --check
```

- `test/adapter.test.js` проверяет делегирование ядру на временном Git-репозитории.
- `test/plugin.test.js` проверяет регистрацию инструментов в изолированном
  OpenCode 1.19.3 без LLM; без подходящего бинарника тест пропускается.
- Для проверки опубликованного пакета задайте `GITWT_TEST_PLUGIN_SPEC` и запустите
  `node --test test/plugin.test.js`. Не меняйте пользовательский конфиг ради теста.
- Проверки Git-ядра находятся в `gitwt`; не дублируйте их здесь.

## Git и выпуск

- GitHub — основной репозиторий; SourceCraft — зеркало. Изменения через ветку и PR,
  без прямых push в main, force-push и изменения выпущенных тегов.
- Не менять чужие незакоммиченные правки. Commit/push/merge и публикация только
  по просьбе пользователя. После merge удалять локальную ветку через `git branch -d`.
- Тег `vX.Y.Z` должен совпадать с package.json/lock-файлом и указывать на влитый коммит.
  GitHub Actions выполняет checks → mirror → publish; SourceCraft не публикует npm.
- `NPM_TOKEN` и `SOURCECRAFT_TOKEN` — GitHub Secrets, значения не выводить.
- В конце коммитов и внешних сообщений добавлять один блок:

```text
---
Co-Authored-By: LLM
Model: <имя модели без префикса провайдера>
```
